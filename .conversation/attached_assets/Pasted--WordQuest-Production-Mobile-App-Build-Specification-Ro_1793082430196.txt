# WordQuest — Production Mobile App Build Specification

## Role

Act as a senior React Native engineer, mobile game developer, UI/UX designer, QA engineer, and Android release engineer.

Build a complete, production-oriented native mobile word-search puzzle game named **WordQuest**. This must be a working application, not a static prototype, mockup, or web page disguised as a mobile app.

## 1. Project configuration

- App name: WordQuest
- Android package ID: `com.wordquest.puzzle`
- Version: `1.0.0`
- Version code: `1`
- Primary platform: Android
- Framework: React Native with the current stable compatible Expo SDK
- Language: TypeScript
- Navigation: Expo Router
- Gestures: React Native Gesture Handler
- Persistence: AsyncStorage
- Audio: `expo-audio` or the current supported Expo audio package
- Ads: `react-native-google-mobile-ads`, integrated through a compatible native build
- Backend: NestJS, with only `GET /health` returning `{ "status": "ok" }`
- No authentication, leaderboard, user accounts, cloud save, or remote gameplay dependency.

Use compatible dependency versions. Do not force-install incompatible versions or silently downgrade the Expo SDK.

## 2. Architecture

Organize the project into:

- `app/`: five primary screens and navigation
- `src/data/`: all 15 categories and curated bonus dictionary
- `src/engine/`: grid generation, placement, selection validation, scoring and game rules
- `src/components/`: reusable UI components and letter grid
- `src/hooks/`: timer and game-state hooks
- `src/services/`: persistence, audio and advertising
- `src/theme/`: colors, spacing, typography and highlight palette
- `src/types/`: shared TypeScript types
- `tests/`: unit and integration tests for game logic
- `backend/`: minimal NestJS health service

Keep the game engine independent of React components. Use strict TypeScript types, deterministic test fixtures, clean error handling, and documented public interfaces.

## 3. Screens

Implement all five screens:

1. Home: WordQuest logo, animated Play button, coin balance and attractive light-theme design.
2. Category Select: scrollable grid of 15 category cards in the exact specified order, with emoji, name and lock/unlock state.
3. Mode Select: Classic and Time Mode options.
4. Game: interactive letter grid, word list, score, timer, hints, coins and game feedback.
5. Results: final score, words found, bonus words, time taken, earned coins and navigation buttons for Play Again, Next Level and Home.

Use native React Native layouts. Support different Android screen sizes and safe areas. Use a consistent design system rather than five unrelated designs.

## 5. Grid generation

Apply these rules in order:

- If the category has at least 16 words OR the longest word has at least 10 characters, use 12×12.
- Otherwise, if the category has at least 12 words OR the longest word has at least 7 characters, use 10×10.
- Otherwise, use 8×8.

Place words in all eight straight-line directions. Support overlapping letters when they match. Reject conflicting placements and retry safely. Fill remaining cells with random uppercase letters.

Use bounded placement attempts, deterministic random seeds in tests, and clear errors if a board cannot be generated. Never silently omit a required word. Validate every generated board automatically.

## 6. Gesture selection

Use React Native Gesture Handler to implement finger dragging across the grid.

- Identify the start and end cells accurately.
- Allow horizontal, vertical and diagonal straight-line selections in both directions.
- Validate the complete selected sequence against unfound puzzle words.
- Reject bent, disconnected or invalid selections.
- Provide visual feedback during dragging.
- Prevent duplicate scoring for already-found words.
- Handle gestures safely near cell boundaries and on smaller devices.

## 7. Game modes and scoring

Classic Mode:
- No countdown.
- Timer counts upward from zero.
- Completion occurs when all required puzzle words are found.

Time Mode:
- Starts at 120 seconds.
- Countdown reaches zero and triggers game over if the puzzle remains incomplete.
- Timer turns red below 30 seconds.
- Award a completion time bonus of remaining seconds multiplied by two.

Scoring:
- Puzzle word: +10 points.
- Valid bonus word: +5 points.
- Time Mode completion bonus: remaining seconds × 2.
- No duplicate scoring.

Pause timers when the app backgrounds or the game screen is not active, according to an explicit game lifecycle policy. Calculate time from timestamps rather than assuming intervals are perfectly accurate.

## 8. Bonus-word dictionary

Include a curated set of at least 600 common English words, primarily three- and four-letter words, in a local `Set<string>` for efficient membership checks.

Award +5 for a valid bonus word that:
- Contains at least three letters.
- Is in the curated dictionary.
- Is not part of the current puzzle's word list.
- Has not already been awarded in this puzzle.

Bonus-word selection must use the same straight-line gesture rules as normal word selection. Document that the curated set is not a complete English dictionary.

## 9. Hints

- Start each puzzle with three hints.
- Display the remaining hint count as a red badge on the lightbulb button.
- Disable the free-hint action when no hints remain.
- Select a random unfound puzzle word.
- Highlight its cells in yellow and flash three times over 1.5 seconds.
- Consume exactly one hint per successful hint action.
- If all words are found, do not consume a hint.
- Provide an optional rewarded-ad route for extra hints when ads are configured.

## 10. Coins and progression

- Initial coin balance: 300.
- First eligible completion of a category: +50 coins.
- Persist coins and completed category IDs with AsyncStorage.
- Animals is always unlocked.
- Category i is unlocked only if the immediately preceding category ID is present in completedLevels.
- Use stable category IDs rather than array indexes in persisted data.
- Replays must not award the same one-time category completion reward again.
- Prevent duplicate completion events from granting multiple rewards.
- Validate and recover malformed or outdated local save data.

## 11. Visual design

Light theme:
- Background: `#f0f0f3`
- Blue: `#2f80ed`
- Orange: `#ff8c1a`
- Pink: `#f83f8f`
- Primary text: `#1a1a1a`
- Found-word text: `#c0c0c8`

Implement all 18 highlight color families specified by the user. Use approximately 35% opacity for found-word cell backgrounds. Keep text readable and ensure found, selected, hinted and unfound states are distinguishable beyond color alone.

Use polished cards, rounded buttons, restrained shadows, fluid transitions and responsive spacing. Avoid excessive animations that interfere with gameplay.

## 12. Sound effects

Bundle lightweight, royalty-free local audio files totaling less than 500 KB.

Support:
- Button tap
- Correct word found
- Wrong selection
- Level complete
- Countdown tick below 30 seconds
- Drag/swipe
- Bonus word found
- Game over

Centralize playback in an audio service. Handle missing files, audio initialization failures and overlapping playback gracefully. Include a sound toggle and avoid requiring network access.

## 13. AdMob — configure later

Implement an advertising service abstraction with:
- Mock provider for initial development.
- Interstitial ad interface.
- Rewarded ad interface.
- Explicit readiness and failure states.
- No ad dependency for core gameplay.

Reserve configuration fields for:
- AdMob App ID
- Interstitial Ad Unit ID
- Rewarded Ad Unit ID

When native ads are enabled:
- Configure the Android manifest App ID through the appropriate Expo config plugin.
- Use Google test ads during development.
- Show interstitial ads only on eligible transitions, every second eligible trigger, with at least 60 seconds between displays.
- Grant extra hints only after the rewarded ad's reward callback confirms completion.
- Never deduct coins or block game completion because an ad failed.
- Do not display interstitials during a drag gesture, active puzzle interaction, or immediately after another ad.
- Respect consent, privacy and applicable Google Play and AdMob policies.

Do not insert invented production IDs. Until credentials are provided, keep ads disabled or mocked and document how to enable them.

## 14. Offline behavior

All category data, puzzle generation, scoring, bonus-word validation, hints, timers, progression and sound assets must be available locally.

The app must start and play without internet access. Ads and the optional health endpoint are the only network-dependent components.

## 15. NestJS backend

Create a separate minimal NestJS service with:

`GET /health` → HTTP 200 and `{ "status": "ok" }`

Do not introduce a database, authentication, analytics backend or cloud save. The mobile app must never require this endpoint for gameplay.
