# Optional AdMob setup

WordQuest remains free and ad-supported. Development and preview use Google's
official test IDs; production requires the Android AdMob App ID and banner,
interstitial, and rewarded unit IDs. Gameplay, local saves, puzzle completion,
and hints remain independent of ad availability.

## Current placements and gating

- Home and category screens mount an anchored adaptive banner in a reserved
  bottom slot after UMP permits ad requests. The puzzle and results screens have
  no banner.
- The existing extra-hint action requests a rewarded ad. A hint is granted only
  after the rewarded SDK emits its earned-reward callback; failure, no fill,
  timeout, or early close grants nothing.
- Interstitial eligibility is counted from successful puzzle completions and
  evaluated only when the user taps a results-screen transition. It requires at
  least three completions since the previous shown ad and a three-minute
  minimum interval. An unavailable ad never delays navigation.
- The Android provider persists the interstitial schedule locally. Web and
  unsupported platforms use the no-op provider.

## Consent and development

The app calls `AdsConsent.gatherConsent()` at launch and checks
`canRequestAds` before initializing Google Mobile Ads or mounting banners. If
consent gathering fails, the provider checks UMP's cached consent result and
fails closed if it cannot confirm requests are allowed. The home screen exposes
a privacy-options entry point; UMP presents its form when the current message
requires it.

To test UMP, configure the relevant consent messages in AdMob and use an Android
development build, not Expo Go. A development-only test can call
`adProvider.initialize({ debugGeography: 'EEA',
testDeviceIdentifiers: ['<device-hash>'] })`; get the hashed device ID from
native Google Mobile Ads logs. `AdsConsent.reset()` resets UMP state between
tests. `EXPO_PUBLIC_ADMOB_PROFILE` defaults to `test` in local development and
is explicitly set to `test` in the EAS preview APK profile. The preview
profile supplies Google's official test App ID and unit IDs. A local native
development build must provide those same test values in its Expo environment;
without IDs the Android ads provider remains disabled. Expo Web uses the
no-op provider.

## Production Android configuration

The EAS production profile targets a store AAB and enables automatic version-code
increments. It sets `EXPO_PUBLIC_ADMOB_PROFILE=production` and uses the Expo
project's `production` environment. Before a production build can proceed, add
these four variables to that EAS environment:

- `EXPO_PUBLIC_ADMOB_ANDROID_APP_ID`
- `EXPO_PUBLIC_ADMOB_BANNER_UNIT_ID`
- `EXPO_PUBLIC_ADMOB_INTERSTITIAL_UNIT_ID`
- `EXPO_PUBLIC_ADMOB_REWARDED_UNIT_ID`

Use the values generated by WordQuest's Android app and ad units in AdMob. The
config plugin validates their format, requires all four to use the same AdMob
publisher, rejects Google's sample IDs, and stops configuration with a clear
error when any value is missing. Production never falls back to test IDs.

AdMob App and ad-unit IDs are public identifiers embedded in the Android
application, not passwords or API secrets. Keep production values out of source
control and set them in the Expo project's production environment variables.
Replit cannot configure the external EAS environment for this project; this
must be completed in the Expo project settings. The preview profile stays on
Google test IDs.

Expo SDK 57 uses `react-native-google-mobile-ads` 17.4.0 and
`expo-build-properties` 57.0.22. Android min SDK is 24, target SDK is 36, and
the UMP ProGuard keep rule is configured. A custom native build is required; Expo Go and Expo Web
use the no-op provider. The ads library contributes `INTERNET`, `WAKE_LOCK`,
and `ACCESS_NETWORK_STATE`; these do not trigger runtime permission prompts.
